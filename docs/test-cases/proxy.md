# 网络代理

用例文件：`e2e/proxy-settings.spec.ts`（本页所有自动化用例都在这里）

规范与状态含义见 [README.md](./README.md)。

## 切到「自定义」并填写代理地址与直连规则

用户把模式从「跟随系统」切到「自定义」，填入代理地址和直连规则。设置页没有保存按钮，
改动靠页面防抖自动保存，所以要证明的是「值真的写进了配置文件」，而不是「输入框里还留着字」。

- 该看到：重进页面后下拉停在「自定义」，两个输入框回显刚才填的值——值来自后端回读，不是页面残留。
- 用例：**[SET-PRX-01]** 切到自定义并填写代理地址与直连规则后落盘，重进页面仍回显
- 落盘断言：`proxy.mode`、`proxy.url`、`proxy.bypass_rules`

## 切到「不使用」

- 该看到：模式回显「不使用」，且该模式下地址和直连规则的输入框整个消失（用不到的东西不该露出来）。
- 用例：**[SET-PRX-02]** 切到不使用代理后模式落盘，重进页面仍回显且不再展示地址输入
- 落盘断言：`proxy.mode`

## 改完立刻切到别的设置栏目

用户填完代理地址后常常直接点侧边栏去别的设置页，不会专门等一会儿。这一条要证明的是：
**离开这一页时挂起的改动也会被提交**，不会因为「还没到防抖时间」就静默丢掉——
丢值正是「页面上填了、实际没保存」最常见的触发方式。

- 该看到：切回来时下拉停在「自定义」，地址回显刚才填的值（来自后端回读）。
- 用例：**[SET-PRX-05]** 改完立刻切到别的设置栏目，代理模式与地址仍会落盘并在重进后回显
- 落盘断言：`proxy.mode`、`proxy.url`
