# 设置页通用的保存时机

用例文件：`e2e/settings-autosave.spec.ts`（本页所有自动化用例都在这里）

规范与状态含义见 [README.md](./README.md)。

设置页没有保存按钮，改动由 `useAutoSaveSettingsForm` 在 600ms 防抖后自动保存。
防抖窗口就是这类「填了没保存」的高发区，所以单独一页记时机问题。

## 改完立刻切到别的设置栏目

用户在网络代理页改完，不等那 600ms 就切到外观页。切栏目会让上一个设置页卸载，
如果卸载时只是把定时器清掉，挂起的改动就随页面一起丢了。

- 该看到：切走的改动仍然落盘；切回网络代理页时看到的是新值而不是旧值。
- 用例：**[SET-AUTO-01]** 改完立刻切到别的设置栏目，改动仍会落盘并在重进后回显
- 落盘断言：`proxy.mode`、`proxy.url`

## 还没覆盖的场景

### 在防抖窗口内直接关窗 / 退出应用

- 现状：切栏目会触发卸载前的冲刷，关窗走的是另一条路径（应用退出），还没验过。
- 编号：**[SET-AUTO-02]**（未覆盖）

### 保存失败后立刻切走

- 现状：失败横幅挂在页面上，页面已经卸载，错误还能不能露给用户没人验。
- 编号：**[SET-AUTO-03]**（未覆盖）
